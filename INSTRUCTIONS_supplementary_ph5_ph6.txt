% PART F — HOW EXISTING RESULTS CANNOT BE OVERWRITTEN (item 8)
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

1. Separate root: every supplementary write goes under
   --output-root (default results/supplementary_ph56/), a directory that does
   not intersect any canonical tree.
2. Root safety check: src/supp_paths.check_root_safety() REFUSES any
   --output-root that equals or lies inside results/stage26_validation,
   results/stage33_gsl_canonical, results/stage40_canonical,
   results/stage59_ph56_horizon, or results/ itself (validated: pointing the
   scripts at results/stage40_canonical raises ValueError).
3. No-overwrite default: atomic_save_npy/atomic_save_json call guard_output(),
   which raises FileExistsError if the target exists unless --overwrite is
   passed (validated by unit test). Existing supplementary artifacts are
   therefore REUSED, not clobbered, on re-runs.
4. Lambda-tagged filenames: graphs live in graphs_lambda002/ vs
   graphs_lambda001/; results in training_lambda002/ vs training_lambda001/;
   every filename contains dataset + PH + lambda tag + type (+ seed), so the
   0.01 and 0.02 runs can never collide with each other or with canonical
   names (which carry no lambda tag at all).
5. Canonical reads are read-only: the canonical-reuse path only ever
   np.loads stage26/stage33 files (checksums recorded in sidecars); no
   canonical path is ever passed to a save helper.
6. Aggregator reads ONLY the supplementary root and writes only
   supplementary_summary.{json,csv} there; main-paper tables are untouched.
