\section{General Response (Summary)}

Thank you for the constructive reviews of the submitted manuscript. The revision keeps the paper's identity as a study of \textbf{graph structure learning for traffic forecasting}, with a stronger focus on \textbf{whether learned sparse graphs help because of sparsity alone or because of where edges are placed}, and on comparison with the \textbf{physical road-network adjacency}.

Throughout this letter, an identity-adjacency model (\emph{T-GCN-NoSpatial} / \emph{GCN-NoSpatial}) is used only as a reference control when judging learned structure; it is not proposed as a forecasting method.

\textbf{Two comments drove substantial experimental redesign:}
\begin{itemize}
    \item \textbf{R1-W4 (temporal interpretation of the learned DAG):} We separated contemporaneous vs.\ explicit multi-lag DAGMA constructions and removed the temporal-DAG claim.
    \item \textbf{R1-W5 (sparsity / oversmoothing / fair controls):} We added matched-edge-budget sparsity controls, structure figures, capacity checks, and a no-graph reference so that gains over the physical graph cannot be attributed only to having fewer edges.
\end{itemize}

Together these changes added on the order of \textbf{six pages} of new experimental material, controls, and discussion (new tables, structure and control figures, sparsity sweep, temporal-resolution control, and a rewritten Limitations section). The resulting evaluation is more comprehensive and better controlled than the submitted version.

\subsection*{Additional experiments carried out in this revision}

The following experiments and evaluations are new relative to the submitted manuscript. They are described in more detail in the point-by-point responses (especially R1-W5, R1-W6, and R1-W7).

\begin{enumerate}
    \item \textbf{Five-seed main protocol.} All primary forecasting configurations were retrained under seeds $\{42,43,44,45,46\}$; Tables~2--3 report mean RMSE with sample standard deviations, together with paired per-seed win counts (Section~4.4, ``Statistical reporting'').
    \item \textbf{Matched-sparsity controls.} On Los-loop PH1, RandTop30 (random directed edges) and CorrTop30 (top training correlations) were compared with the DAGMA multi-lag graphs at the same $30$-edge budget (Table~4; Figure~7).
    \item \textbf{Edge-budget sweep.} The same heuristic families were evaluated for $K\in\{10,20,30,50,80\}$ directed edges (Table~5; Figure~6).
    \item \textbf{Capacity control.} A graph-free T-GCN with hidden dimension $74$ (parameter-matched to Mix) was trained as a single-seed check that extra gate parameters do not explain the multi-lag gain (Table~4, lower block).
    \item \textbf{Temporal-resolution control.} Los-loop was resampled to $15$-minute steps and the multi-lag comparison was repeated under the same five-seed protocol (Section~4.6; Table~6).
    \item \textbf{Structure and qualitative figures.} Physical vs.\ learned multi-lag graph structure with degree histograms (Figure~5); per-seed RMSE distributions (Figure~8); predicted-vs-actual overlays on Los-loop and SZ-Taxi (Figures~9--10).
    \item \textbf{Reference adjacencies.} In addition to the physical road-network graph, all main tables include an identity (no off-diagonal structure) reference so that a gain over Physical is not treated as sufficient evidence by itself.
\end{enumerate}

\textbf{Numbers relative to the submitted version.} Because the evaluation pipeline and especially the DAGMA graph-learning code were substantially revised, absolute RMSE values and relative percentages differ in places from the submitted manuscript. The experimental \emph{protocol} (two public benchmarks, four horizons, physical baseline) is the same, but the revised tables are the authoritative numbers. We therefore restate the main claims from the current artifacts rather than reusing the submitted abstract's percentages.

\textbf{Structural changes relative to the submitted version (also recorded in the repository README).}
\begin{itemize}
    \item The submitted ``Hardware specifications and hyperparameter settings'' table was removed; training settings are described compactly in the Experimental Setup, and hardware/software details are documented in the repository README for reproducibility.
    \item Algorithm~1 (NOTEARS) and the detailed DAGMA algorithm box were removed. The revised Method cites the original papers and describes only the constructions actually used (contemporaneous and multi-lag).
    \item Dense multi-panel convergence grids were replaced by compact final-metric tables and a short appendix training-loss figure.
\end{itemize}

\reviewercomment{
\textbf{R1-W4.} The temporal interpretation of the learned DAG in Section~5.1 is asserted rather than demonstrated. The claim that an edge $j \to i$ represents ``$j$ at time $t$ predicting $i$ at time $t+1$'' does not obviously follow from the description in~3.2. Please clarify explicitly how the input to DAGMA is constructed, since this is load-bearing for the Section~5 discussion.
}

\response{
We agree this was load-bearing and was not demonstrated in the submitted version. The revision separates two constructions and \textbf{retires} the claim that the contemporaneous DAG is a temporal graph.

\begin{enumerate}
    \item \textbf{Contemporaneous GSL (Method Section~3.2).}
    DAGMA is fitted to simultaneous per-sensor snapshots $\mathbf{X}=\mathrm{train\_norm}[0::\mathrm{PH}]$ (one row = all $N$ sensors at the same time; \textbf{no lag blocks}). An edge is a \textbf{statistical association among present observations}; it does \textbf{not} encode ``sensor $j$ at time $t$ predicts sensor $i$ at time $t+1$.''

    \item \textbf{Multi-lag construction (Method Section~3.3) carries temporal organization explicitly.}
    Input $Z=[x(t-3),\,x(t-2),\,x(t-1),\,x(t)]$ with $(L+1)N$ variables; lag-specific binary blocks $\mathbf{A}_1,\mathbf{A}_2,\mathbf{A}_3$ are extracted by absolute-magnitude thresholding.

    \item \textbf{Old Section~5 apparatus removed.}
    The submitted ``spatial graph vs temporal dependency graph'' paradox section is not in the revised paper. The GSL/cGSL asymmetry is discussed only as an aggregation-compatibility observation (Discussion Section~6.2).

    \item \textbf{Contemporaneous vs lagged evidence (also relevant to Q4).}
    The two constructions are specified side by side in Sections~3.2--3.3; Results Section~5.4 compares single contemporaneous graphs with multi-lag graphs and with static-union vs lag-aligned use of the \textbf{same} multi-lag artifacts (Tables~2--3).
\end{enumerate}

\textbf{Location:} Method Sections~3.2--3.3; Discussion Section~6.2.
}

\reviewercomment{
\textbf{R1-W5.} No hyperparameter optimization was performed for the baselines/learned models, and the learned graphs are likely much sparser than the physical graph. Please report the density/degree distribution of learned vs.\ physical graphs, and check whether some of the reported gains are attributable to reduced oversmoothing from sparsity rather than the specific learned structure. A minimal hyper-parameter sweep would help establish whether a fairer baseline narrows the gap.
}

\response{
Together with R1-W4, this comment led to a \textbf{major redesign of the evaluation}, with the main question framed as: \emph{does a learned sparse graph help because it is sparse, or because of how its edges are placed and used?}

\paragraph{(a) Density of physical vs learned graphs}
\begin{itemize}
    \item \textbf{Physical Los-loop:} $2626$ off-diagonal edges; mean degree $\approx 12.69$.
    \item \textbf{Learned multi-lag union (Los-loop):} $28$ edges after consumer thresholding; mean degree $\approx 0.14$.
    \item \textbf{Contemporaneous GSL:} $28$ (Los-loop) and $8$ (SZ-Taxi) directed edges at every PH.
\end{itemize}
These statistics appear in \textbf{Figure~5} (``Los-loop graph structure: physical adjacency; multi-lag union after consumer thresholding; node degrees'') and in Method Sections~3.2--3.3.

\textbf{Location:} Figure~5 (graph structure); Method Sections~3.2--3.3.

\paragraph{(b) Sparsity alone does not explain the multi-lag gain (Los-loop PH1)}
The paper's primary comparison remains \textbf{learned adjacency vs.\ the physical road-network graph}. To separate structure quality from density and from removing the graph entirely, the evaluation adds \textbf{matched edge budgets} and a \textbf{graph-free baseline}:

\begin{enumerate}
    \item \textbf{Graph-free baseline} (identity adjacency).
    On these data, dropping the physical graph often reduces error. We therefore treat a gain over Physical as necessary but not sufficient, and ask whether a learned graph also beats this control. Single contemporaneous GSL/cGSL \textbf{do not} beat the graph-free baseline on these benchmarks; multi-lag graphs with lag-aligned use on Los-loop \textbf{do}.

    \item \textbf{Matched-sparsity controls at a common $30$-edge budget (Los-loop PH1 only).}
    \begin{itemize}
        \item RandTop30 (random): \textbf{worse} than the graph-free baseline;
        \item CorrTop30 (top training correlations): \textbf{worse} than the graph-free baseline;
        \item DAGMA multi-lag edges with lag-aligned use (MultiGSL / Mix): \textbf{better} than the graph-free baseline.
    \end{itemize}
    Thus \textbf{sparsity alone does not explain} the multi-lag result on this cell; \textbf{edge placement and use} matter. We do not claim this for all datasets or horizons.

    \textbf{Edge-budget sweep (new).} We extended this control across $K\in\{10,20,30,50,80\}$ directed edges on Los-loop PH1 (five seeds; Table~5; Figure~6, ``Edge-budget sweep on Los-loop PH1''). For every $K$, both RandTopK and CorrTopK remain \textbf{at or above} the graph-free baseline. At the same $30$-edge budget, the main MultiGSL ($4.84$) and Mix ($4.49$) remain well below both heuristic families and below Physical.

    \item \textbf{Capacity control (single seed, labeled).}
    A hidden-$74$ graph-free model matching Mix's parameter count stays near the hidden-$64$ graph-free error, so the gate's extra parameters do not by themselves explain the Los-loop multi-lag result (Table~4, lower block).

    \item \textbf{Oversmoothing language.}
    Dense-graph degradation is described as \textbf{consistent with} excessive neighborhood mixing or an unsuitable inductive bias; we do not claim we measured oversmoothing directly (Discussion Section~6.1).
\end{enumerate}

\textbf{Location:}
\begin{itemize}
    \item Section~4.5 (Matched-Sparsity and Capacity Controls).
    \item Section~5.3 (Is the Gain Only Sparsity?): Table~4, Table~5, Figure~6, Figure~7.
    \item Discussion Section~6.1; Limitations Section~6.5 (control scope).
\end{itemize}

\paragraph{(c) Hyperparameter optimization / fairer baseline}
\textbf{We respectfully did not run a full hyperparameter search, a sparsified physical graph, or a $\lambda$/threshold sweep.} Those would require a substantially larger experimental grid than the other revisions combined. What we did add is a no-graph reference and budget-matched controls --- the minimal fair checks required under a five-seed protocol. The omitted sweeps are listed explicitly as limitations and future work rather than left implicit.

\textbf{Location:} Section~6.5 (Limitations and Future Work); Conclusion (future work).

\reviewercomment{
\textbf{R1-W6.} No significance testing, variance, or multiple seeds are reported, despite acknowledging stochastic elements in training. Please report mean $\pm$ std over at least 3--5 seeds for the main results tables.
}

\response{
The submitted version reported essentially single-run numbers; the revision adds repeated evaluation and a clear reporting policy.

\textbf{Multiple seeds.} All main forecasting configurations are trained under five seeds $\{42,43,44,45,46\}$. DAGMA graphs are fitted once and remain deterministic across those seeds, so the five runs quantify \textbf{training variability of the forecasting models}, not re-estimation of the graph.

\textbf{Variance in the tables.} The main T-GCN and GCN results tables (\textbf{Tables~2--3}) report \textbf{mean RMSE with sample standard deviations} ($\mathrm{ddof}=1$) over the five seeds. Captions note that bold marks the lowest mean, not a claim of statistical significance.

\textbf{How multi-seed evidence is interpreted.} Primary weight is placed on \textbf{effect size}, \textbf{five-seed means and spreads}, and \textbf{paired per-seed consistency}. For example, on Los-loop, Mix beats the graph-free baseline in $5/5$ seeds at every PH1--PH4, and the graph-free baseline beats Physical in $5/5$ seeds in all eight dataset$\times$horizon cells. On SZ-Taxi, Mix and the graph-free baseline are within seed spread.

\textbf{Paired $t$-tests.} Where the Mix vs graph-free-baseline comparison is discussed on Los-loop, we also report paired $t$-tests on per-seed RMSE differences \textbf{for reference} (Section~5.4; also stated in the statistical-reporting paragraph of Section~4.4). These are exploratory: we do not present them as formal proof of superiority, and they are not repeated in the tables.

\textbf{Significance language.} With $n=5$, the exact two-sided Wilcoxon signed-rank test cannot attain $p<0.0625$. We therefore avoid definitive ``statistically significant'' claims and state this limitation in the statistical-reporting policy (Section~4.4) and under Limitations (Section~6.5).

A per-seed distribution figure on Los-loop (\textbf{Figure~8}, ``Los-loop per-seed test RMSE for the multi-lag use ladder'') complements the tables; its means match Table~2.

\textbf{Location:} Section~4.4 (paragraph ``Statistical reporting''); Tables~2--3; Section~5.4; Figure~8; Section~6.5.
}

\reviewercomment{
\textbf{R1-W7.} Results are only reported up to prediction horizon~4. Please report how performance (and the GSL/cGSL gap) evolves at longer horizons.
}

\response{
Forecast horizons of four steps are also used in several standard traffic-forecasting evaluations, including T-GCN and A3T-GCN (Zhao et al., 2020). That convention is relevant context, but it does not replace a direct analysis of longer horizons. To address the concern, we added a temporal-resolution control on Los-loop and state the horizon scope of our claims explicitly.

\textbf{Canonical horizons.} The main experiments use $\mathrm{PH}=1$--$4$ at each dataset's native sampling interval (5--20 minutes on Los-loop; 15--60 minutes on SZ-Taxi). \textbf{We did not run PH5--8 (or longer) on the native 5-minute Los-loop series}, because the revision already required a substantial re-evaluation under W4--W6, and because a wall-clock-matched control on a resampled series was available at lower cost. That choice is stated as a scope limitation rather than presented as a substitute for a full long-horizon study.

\textbf{Temporal-resolution control (15-minute Los-loop).} Los-loop was resampled to 15-minute steps by averaging consecutive triplets, and the multi-lag comparison was repeated under the same five-seed training protocol (Section~4.6; Table~6). In that variant, $\mathrm{PH}=1,2,3,4$ correspond to \textbf{15, 30, 45, and 60 minutes} ahead. In wall-clock terms these horizons match \textbf{PH3, PH6, PH9, and PH12} on the native 5-minute grid; they are not equivalent to directly evaluating those PH values on the original 5-minute data. On the 15-minute series, Mix reduces RMSE versus the graph-free baseline by $27.4\%$, $21.4\%$, $19.8\%$, and $16.1\%$ at $15$--$60$ minutes, with $5/5$ seed wins at each step (Section~5.5; Table~6). This experiment reports the graph-free baseline, MultiGSL, and Mix only; it does not include separate GSL/cGSL rows.

\textbf{Scope of the claims.} The paper studies the effect of graph structure and its use for short-horizon forecasting at PH1--4. Conclusions are limited to that range. The GSL/cGSL comparison is likewise limited to PH1--4 on the native grids; we do not claim a GSL/cGSL gap analysis beyond PH4 at 5-minute sampling.

\textbf{Location:} Section~4.6 (Temporal-Resolution Variant); Section~5.5; Table~6; Section~6.5 and Conclusion (future work).
}

\reviewercomment{
\textbf{R1-W9.} The paper lacks an explicit limitations/weaknesses discussion. Please add a paragraph addressing scalability of DAGMA to larger road networks, sensitivity to the sparsity hyperparameter $\lambda$, and the fact that only two (relatively dated) backbones were tested.
}

\response{
A dedicated Limitations discussion was added (Section~6.5) and covers the three issues raised, together with other scope conditions of the study.

\textbf{DAGMA scalability and cost.} Graph estimation with DAGMA is the heavier offline stage compared with ordinary forecasting-model training on these data. Measured costs in our runs are on the order of tens of minutes per horizon for a contemporaneous fit with $O(10^2)$ sensors and on the order of a few hours for the $828$-variable multi-lag fit on Los-loop (CPU). For a fixed dataset and construction, the graph is estimated \textbf{once} and reused for every forecasting seed, epoch, and test sample. Scalability to substantially larger road networks remains an open question.

\textbf{Meaning of $\lambda$.} The reviewer's $\lambda$ refers to the DAGMA sparsity regularization coefficient $\lambda_1$. In the revision, $\lambda_1$ is $0.02$ (Los-loop) and $0.01$ (SZ-Taxi) for the contemporaneous construction (Section~3.2), and $0.01$ (both datasets) for the multi-lag construction (Section~3.3). Support thresholds are separate. A systematic sensitivity analysis of $\lambda_1$ was not included and is listed as future work (Section~6.5 and Conclusion).

\textbf{Backbone coverage.} The study uses GCN and T-GCN as relatively established spatial and spatiotemporal backbones, providing a controlled setting for comparing graph construction and how the graph is used. Results should not be generalized automatically to all newer attention-based, adaptive-graph, or transformer-style models; evaluating the same constructions on those architectures is a natural extension.

\textbf{Other limitations (concise).} Two datasets; PH $\le 4$ at native sampling (the 15-minute Los-loop study is a resolution control, not PH5--8 on 5-minute data); matched-sparsity/capacity controls only on Los-loop PH1; static learned graphs (Mix changes use, not the edge set); five forecasting seeds ($n=5$).

\textbf{Location:} Section~6.5 (Limitations and Future Work); Conclusion (future work: $\lambda_1$/threshold sensitivity, longer 5-minute horizons, other backbones).
}

\reviewercomment{

\response{

\reviewercomment{
\textbf{R1-Q4.} On the DAG/traffic paradox discussed in Section~5: since the resolution hinges on DAGMA learning a temporal rather than spatial graph, can you provide direct evidence (e.g., the lagged data construction, or an ablation feeding genuinely simultaneous vs.\ lagged data into DAGMA) that supports this interpretation, rather than it being inferred post hoc from the GSL/cGSL performance split?
}

\response{
We agree that the temporal interpretation must come from the \textbf{input construction}, not from a post-hoc reading of the GSL/cGSL split. The revision therefore separates two constructions explicitly:

\begin{enumerate}
    \item \textbf{Contemporaneous GSL:} DAGMA on simultaneous snapshots $\mathbf{X}=\mathrm{train\_norm}[0::\mathrm{PH}]$ (no lag blocks). An edge is a present-time statistical association; it is \textbf{not} interpreted as $j$ at $t$ predicting $i$ at $t+1$ (Method Section~3.2).
    \item \textbf{Multi-lag:} DAGMA on $Z=[x(t-3),\ldots,x(t)]$ with lag-specific binary blocks $\mathbf{A}_1,\mathbf{A}_2,\mathbf{A}_3$ (Method Section~3.3).
\end{enumerate}

Empirically, the \textbf{same multi-lag artifacts} used per timestep in T-GCN and unioned statically in GCN yield very different errors (Table~2 vs Table~3: e.g.\ T-GCN-MultiGSL $4.84$ vs GCN-MultiGSL $9.78$ on Los-loop PH1), and single contemporaneous graphs do not beat the graph-free control. The old Section~5 ``DAG paradox'' apparatus is removed; the cGSL/GSL contrast is treated only as an aggregation-compatibility observation (see R1-W4).

\textbf{Location:} Method Sections~3.2--3.3; Results Section~5.4; Discussion Section~6.2; R1-W4 in this letter.
